# 掲載ページの設計（/case-studies）

<context>
許諾を得た実在の事例を、既存の「想定される活用シーン」とどう共存させるかの仕様。
実装は、実在の事例が1件以上揃ってから実装CCへ依頼する。

法令面の根拠は `README.md`。許諾の取り方は `02_掲載許諾.md`。
</context>

## 1. 共存のさせ方 — 混ぜない

<risk level="high">
実在の事例と想定シーンを、同じ一覧・同じ見た目で並べてはいけない。

読む人にとって区別がつかなくなるだけでなく、
「第三者の客観的な意見のように見える」状態（`README.md` §2）を自分から作ることになる。

**別のセクションに分け、見出し・背景色・ラベルの3つで区別する。**
</risk>

<task>
### ページ全体の並び（上から）

| # | セクション | 状態 |
|---|---|---|
| 1 | パンくずリスト | 変更なし |
| 2 | ヒーロー（h1・リード文） | **リード文を修正**（§7） |
| 3 | **ご利用中のお客様の声（実在）** | **新設**（§4） |
| 4 | データで見る背景（公的統計） | 変更なし |
| 5 | 活用シーンのカテゴリー（フィルター） | 変更なし。**実在事例には適用しない**（§5） |
| 6 | 想定される活用シーン（既存8件） | 見出しとラベルのみ調整（§5） |
| 7 | デジタル名刺活用のヒント | 変更なし |
| 8 | CTA | 変更なし |
| 9 | 関連コンテンツ | 変更なし |

実在の事例を統計セクションより**上**に置く。
このページで最も価値のある情報であり、AI にも読む人にも最初に届くべきものだから。
</task>

## 2. データの持ち方

<task>
`src/components/pages/CaseStudies.tsx` に、既存の `caseStudies` 配列とは
**別の配列**として持つ。同じ配列に混ぜない。

```ts
// 実在の顧客事例。
// 掲載は docs/customer-stories/02_掲載許諾.md の手順で許諾を得たもののみ。
// 許諾を得ていない項目は空にする。推測で埋めることは絶対にしない。
type CustomerStory = {
  company: string;        // 正式名称。掲載許可がない場合は "" にする
  role: string;           // 部署・役職・氏名。許可された範囲のみ
  industry: string;       // 業種
  scene: string;          // お使いの場面（頂いた回答）
  comment: string;        // 頂いた文面のまま。改変しない
  collectedAt: string;    // 例: "2026年8月"
  edited: boolean;        // 本人確認のうえ編集した場合のみ true
  companyUrl?: string;    // 許可がある場合のみ
  logoSrc?: string;       // 許可がある場合のみ
  photoSrc?: string;      // 許可がある場合のみ
};

const customerStories: CustomerStory[] = [];
```

### 決まりごと

- 許可されていない項目は**入れない**。`company` が空なら「製造業のご担当者様」のように
  `industry` と `role` だけで表示する
- `comment` は頂いた文面のまま。語尾を整えるなどの手直しもしない（`README.md` §4）
- `edited` は、本人の確認を得て編集した場合のみ `true`。表示が変わる（§4）
- **配列が空のときは、セクションごと描画しない。**「準備中」も出さない
</task>

## 3. 添える一文（確定文言）

<known-fact>
消費者庁の運用基準 第3の2⑵オ(ｲ) が示す表示例に沿った文言。
根拠は `README.md` §2。**この文言を変えないこと。**

### 通常（`edited` が全件 false のとき）

> 以下は、Share をご利用中のお客様に弊社からご依頼し、ご本人の許諾を得て、
> 頂いた文面のまま掲載しているコメントです。謝礼等の対価はお渡ししていません。

### 編集したものが1件でも含まれるとき

> 以下は、Share をご利用中のお客様に弊社からご依頼し、ご本人の許諾を得て
> 掲載しているコメントです。謝礼等の対価はお渡ししていません。

加えて、`edited: true` のカードには、コメントの直下に次を表示する。

> ※ ご本人の確認を得たうえで編集しています。
</known-fact>

<risk level="high">
### 表示方法の制約（守らないと意味がなくなる）

運用基準 第3の1⑵ は、末尾に置く・小さくする・薄くする・長文にする、を
いずれも「明瞭になっていない」例として挙げている（`README.md` §2）。

- **セクションの冒頭**に置く。カードより上、見出しの直後
- **本文と同じ文字サイズ**にする（`text-sm` 以下にしない）
- **本文と同じ濃さ**にする（`text-gray-400` のような薄い色にしない）
- 折りたたみ・ツールチップ・注釈記号の中に入れない
- ページ末尾に移さない
</risk>

## 4. 実在事例セクションの仕様

<task>
### 見出し
```
h2: ご利用中のお客様の声
```

### 構成
1. h2 見出し
2. §3 の一文（本文サイズ・本文色）
3. カード一覧（1〜2件なら1カラム、3件以上は2カラム）

### カード1枚に載せるもの（上から）

| 要素 | 内容 | 許可がない場合 |
|---|---|---|
| ラベル | 「ご本人の許諾を得て掲載」 | 常に表示 |
| 会社名 | 正式名称。`companyUrl` があればリンク | 省略し、業種のみ表示 |
| 部署・役職・氏名 | 許可された範囲 | 「ご担当者様」 |
| 業種 | バッジ表示 | 常に表示 |
| お使いの場面 | 見出し「お使いの場面」＋本文 | 常に表示 |
| コメント | 引用符付き。他より大きめ・強調 | 常に表示 |
| 編集の注記 | `edited: true` のときのみ | — |
| 取得時期 | 「2026年8月時点」 | 常に表示 |

### 見た目（想定シーンと区別するため）

- 背景: 白
- 枠: `border-primary/30` ＋ 左端に primary 色の縦アクセントバー
- ラベル: primary 背景の白文字バッジ
- 顔写真・ロゴは許可がある場合のみ。**無くても成立する組み方にする**
  （顔写真がないカードが見劣りしない配置にすること）
</task>

## 5. 想定シーンセクションの調整

<task>
既存の8件はそのまま残す。文言も変えない。次の2点だけ調整する。

1. **見出しを明確にする**
   現在: 「すべての活用シーン」「ビジネスでの活用シーン」…
   変更後: 「想定される活用シーン（すべて）」「想定される活用シーン（ビジネス）」…

   既存の説明文「以下は実在の顧客事例ではなく、業種ごとに想定される利用場面の紹介です。」
   は正しいので**残す**。

2. **各カードに「想定例」ラベルを付ける**
   グレー背景のバッジ。実在事例の primary 色バッジと明確に色を変える。

### カテゴリーフィルターは実在事例に適用しない

現在のフィルター（すべて／ビジネス／経営者／フリーランス／マーケティング／イベント）は
**想定シーンだけを絞り込む。**

実在事例をフィルターの対象に含めると、絞り込んだ結果として実在と想定が
同じ一覧に並ぶ場面が生まれ、区別が壊れる。実在事例は常に全件表示のまま固定する。
</task>

## 6. 気になった点を頂いた場合

<task>
`01_依頼文.md` では、良い点だけでなく気になった点も尋ねている。
頂いた場合は、**その部分も含めてそのまま載せる。**

良い部分だけを抜き出すと、運用基準 第2の2⑴キ が禁じる「恣意的な抽出」に当たる
（`README.md` §4）。

載せたくない内容だった場合の扱いは1つだけ:
**その事例を丸ごと掲載しない。** 一部だけ削って載せることはしない。
</task>

## 7. ヒーローのリード文とメタ情報の修正【現時点で不整合あり】

<known-fact>
### 実測した現状（2026-07-26 本番 https://sns-share.com/case-studies）

フェーズ2で本文は想定シーンに作り替えたが、**ページのメタ情報が古いまま残っている。**

| 箇所 | 現在の値 | 問題 |
|---|---|---|
| `title` | デジタル名刺活用事例集 \| 業種別・シーン別の**成功例** \| Share | 中身に成功例はない |
| `description` | …活用した**成功事例**をご紹介…業種別の**導入効果**を… | 中身に事例も効果もない |
| `og:title` | デジタル名刺活用事例集 \| 業種別・シーン別の**成功例** | 同上 |
| `og:description` | **実際のユーザーが語る**デジタル名刺活用術… | **実際のユーザーは語っていない** |

本文には「実在の顧客事例ではなく…想定例です」と書いてあるのに、
検索結果・SNS シェア時には「実際のユーザーが語る成功事例」と表示される状態。

フェーズ2で削除した架空事例と**同じ種類の問題が、メタ情報に残っている。**
本文だけを直してメタ情報を見落とした結果。

対象ファイル: `src/app/case-studies/page.tsx`
</known-fact>

<risk level="high">
**この修正は、実在事例が集まるのを待たずに先に実施する。**
現在進行形で誤った内容が配信されているため。
</risk>

<task>
### 修正案（実在事例が入る前の段階）

```
title:       デジタル名刺の活用シーン集 | 業種別・シーン別 | Share
description: Share（シェア）のデジタル名刺が、展示会・商談・採用イベントなど
             どのような場面で使えるかを業種別にご紹介します。あわせて、
             デジタル名刺が求められる背景を公的統計とともに掲載しています。
og:title:    デジタル名刺の活用シーン集 | 業種別・シーン別
og:description: 展示会、商談、採用イベントなど、デジタル名刺の活用が想定される
             場面を業種別にまとめました。経営者、営業担当者、フリーランスなど
             立場ごとの使い方もご紹介します。
```

### 実在事例が入った後の追記

`description` の冒頭に、実際に頂いたコメントを掲載している旨を1文加える。
件数が確定してから文面を決める。

### ヒーローのリード文（実在事例を追加する時点で修正）

現在（`CaseStudies.tsx` 122〜126行）:
> このページでご紹介するのは実在の顧客事例ではなく、Share（シェア）のデジタル名刺が
> どのような場面で使えるかをまとめた想定例です。

実在の事例を1件でも載せた瞬間、**この文は事実と異なるものになる。** 必ず同時に修正する。

修正後:
> このページには、実際にご利用中のお客様から頂いたコメントと、Share（シェア）の
> デジタル名刺がどのような場面で使えるかをまとめた想定例の両方を掲載しています。
> どちらであるかは、それぞれの見出しに明記しています。
</task>

## 8. 構造化データは追加しない

<known-fact>
`Review` / `AggregateRating` / 星評価のマークアップを入れない。根拠は `README.md` §8。

- 自社サイト上の自社へのレビューは、Google のポリシー上そもそも対象外
- 同じ文面を画面表示と機械向けの2箇所に持つと、更新漏れで食い違う
  （フェーズ2で統計の構造化データを見送ったのと同じ理由）

**AI は画面に表示されているテキストを読む。** 本文として書けば足りる。
</known-fact>

## 9. AI に引用されるための書き方

<task>
このページの目的は AI 検索での可視性。**本文の書き方そのものが対策になる。**

| やること | 理由 |
|---|---|
| 1事例を1つの完結した塊にする | 誰が・どこの・何業・どの場面で・どう使い・どう感じたかが1箇所に揃っていないと、AI が文脈ごと引用できない |
| 会社名は正式名称で書く（前株・後株を含む） | 表記が揺れると同一の会社だと認識されない |
| 業種を明記する | 「製造業の事例は？」という問いに拾われる |
| 取得時期を書く（例: 2026年8月時点） | 情報の鮮度が判断できる |
| 情報を画像の中に入れない | 画像内の文字は読まれない。社名・役職・コメントは必ずテキストで持つ |
| 見出しに「お客様の声」と書く | 何のセクションかが見出しだけで分かる |

**他所に存在しない一次情報である**ことが、このページの価値。
統計や一般論は他サイトにもあるが、この顧客のこのコメントはここにしかない。
</task>

## 10. 件数に応じた段階

<task>
| 実在事例の件数 | 対応 |
|---|---|
| 0件 | セクションを描画しない。§7 のメタ情報修正のみ先に実施 |
| 1〜2件 | セクションを新設。1カラム。h1 は現状のまま変えない |
| 3件以上 | 2カラムに変更。h1 を「デジタル名刺の導入事例と活用シーン」へ変更を検討。**URL は変えない** |
| 5件以上 | 実在事例だけを集めた専用ページの新設を検討 |

**1件でも公開する価値がある。** 揃うのを待たない。
</task>

## 11. 実装CCへ渡すとき

<next-action>
実装を依頼する時点で、次が揃っていること。

- [ ] 許諾済みの事例データ（会社名・役職・業種・場面・コメント・取得時期・掲載可の範囲）
- [ ] `02_掲載許諾.md` の手順4 まで完了し、許諾メールが保存されていること
- [ ] `edited` が true になる事例があるか

実装CCへのプロンプトには、次を必ず含める。

- §3 の文言を**一字一句変えずに**使うこと
- 頂いたコメントの文面を**変えないこと**（語尾の統一・体裁の調整も禁止）
- 事例データを**推測で補完しないこと**。渡したデータのみを使う
- 実在事例と想定シーンを同じ配列・同じ見た目にまとめないこと
- §7 のヒーローのリード文修正を同時に行うこと
</next-action>
